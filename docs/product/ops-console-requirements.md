# 个人运维控制台需求说明

## 产品定位

个人运维控制台是用于管理单机云服务器、应用部署链路和项目运行状态的受保护后台。它不是个人主页，也不是营销展示页；默认用户是系统所有者本人，核心价值是减少登录服务器、翻 GitHub Actions、查 Docker 状态时的上下文切换。

## 目标用户

- Owner：系统所有者，负责账号权限、部署入口、生产配置和最终决策。
- 管理员：负责日常巡检、部署检查、服务状态确认和问题记录。
- 普通用户：只查看授权范围内的服务状态、项目入口和基础运行信息。

## 产品目标

- 登录前只呈现认证入口，不暴露系统内部细节、演示账号、建设过程或路线图。
- 登录后第一屏回答三个问题：当前环境是否可用、当前运行的版本是什么、是否存在需要处理的异常。
- 所有操作入口必须有权限边界，用户能看到自己是否可用，不能把权限规则散落在 UI 文案里。
- 控制台先做只读状态面板，再逐步接入真实操作，例如触发部署、查看日志、管理成员。

## 非目标

- 不做个人介绍页、作品集页、博客页。
- 不在公开登录页展示演示账号或角色说明。
- 不在第一阶段直接实现服务器命令执行、容器重启、数据库写入等高风险操作。
- 不把 GitHub PAT、SSH 私钥、数据库密码等敏感信息展示到 Web 页面。

## 第一阶段范围

### P0 登录与访问控制

- 用户可以通过邮箱和密码登录。
- 登录成功后获得会话令牌。
- 受保护 API 必须校验会话令牌。
- 角色分为 Owner、管理员、普通用户。
- 操作入口根据角色显示可用或权限不足。

验收标准：

- 未登录访问运维概览接口返回 401。
- 登录后可以读取运维概览。
- 普通用户不能使用管理员或 Owner 操作入口。
- 公开登录页不出现演示账号、建设过程、旧页面替换说明。

### P0 运行状态总览

- 展示当前环境名称、入口地址、服务器地址、部署模式。
- 展示 API、Web、Caddy、MySQL 等服务状态。
- 展示最后检查时间。
- 状态必须区分健康、警告、离线。

验收标准：

- 登录后第一屏可以判断系统是否可用。
- 任何状态文本在手机宽度下不溢出。
- 状态颜色和文案一致。

### P1 发布信息

- 展示当前镜像标签或提交标识。
- 展示发布来源，例如 GitHub Actions / GHCR。
- 展示部署方式，例如单机 Docker Compose。
- 预留后续接入部署历史的结构。

验收标准：

- 用户不需要登录服务器即可知道当前运行版本。
- 发布信息不展示敏感配置。

### P1 事件与待处理

- 展示当前异常、警告或待处理项。
- 区分信息、警告、严重等级。
- 每条事件包含状态、更新时间和简短说明。

验收标准：

- 第一屏或第二屏能看到是否有需要处理的事项。
- 没有事件时显示明确的空状态。

### P2 成员与审计

- Owner 可以进入成员管理入口。
- 管理员可以查看部署和巡检入口。
- 普通用户只保留查看入口。
- 后续接入审计日志，记录登录、部署、权限变更。

验收标准：

- 当前阶段可以显示入口和权限状态。
- 真正的写操作在接入审计前保持禁用或只读。

## 信息架构

登录前：

- 系统标识
- 登录表单
- API 可用性状态

登录后：

- 左侧导航：总览、发布、服务、事件、权限
- 总览：环境、角色、健康状态
- 发布：当前版本、镜像、部署来源
- 服务：服务列表和状态
- 事件：异常、警告、待处理项
- 权限：当前角色可用的操作入口

## 迭代顺序

1. 清理登录页文案和布局，使其成为专业认证入口。
2. 重构登录后控制台的信息架构，优先展示环境、发布、服务、事件。
3. 将静态运维数据替换为服务器真实数据。
4. 接入数据库用户表、密码哈希、JWT 过期策略。
5. 接入 GitHub Actions 部署历史和 GHCR 镜像信息。
6. 引入审计日志，再开放高风险操作。

## 风险

- 当前演示账号仍为内存数据，只适合早期验证，不适合长期生产使用。
- 当前会话令牌不是正式 JWT，缺少过期、签名和撤销能力。
- 当前运维概览数据主要是静态数据，尚不能替代真实监控。
- 开放部署或重启操作前必须先具备审计、确认和回滚机制。
